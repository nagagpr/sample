Repo: C:\Work\edas-api-service (FastAPI on AWS Lambda behind API Gateway). The statements and customeraccounts features are both in this app.

GOAL
POST /v1/statements takes cpp_id and an optional customer_account_number. It must return only accounts that are valid in Snowflake AND have a statement folder in S3. Typical sizes: Snowflake returns about 7,000 account numbers for a cpp_id, while S3 has only 4 account folders. Build the response with the least work.

ACCOUNT NUMBER QUERY
Add a new function next to the existing customer-accounts Snowflake code, reusing its connection and config. Don't change the /v1/customer-accounts endpoint. Pass cpp_id as a bind parameter. Never build the SQL with string formatting.

SELECT DISTINCT a.CUSTOMER_ACCOUNT_NBR
FROM DB_MART_MAIN.SCH_MART_MAIN.VW_CUSTOMER_ACCOUNT a
WHERE a.REC_EFF_END_DATE_TIME >= '9999-12-31'
  AND a.INTERNAL_ACCOUNT_CLASSIFICATION_TYPE_ID IN (1, 2)
  AND a.SOURCE_CLIENT_PROGRAM_PARTICIPANT_ID IN (<cpp_id bind>)

FLOW WHEN NO ACCOUNT NUMBER IS GIVEN
1. Validate the request and check the caller can access the cpp_id (existing checks).
2. Run these two at the same time:
   a. The Snowflake query above. Load the results into a Python set of normalized account numbers. No pagination.
   b. One S3 listing of the cpp_id's prefix with Delimiter="/", using a paginator, to get only the account folder names.
3. Match in memory: loop over the S3 folders (the small side) and check each one against the set (the big side). Never make an S3 call per Snowflake account. If folder names are hashes of the account number (like 4f73f38cc4e7 in statement_id), hash each Snowflake number once into a dict {hash: account_number} and look up the folder names in it.
4. Read statement files only for the matched folders, in parallel with a small thread pool, using the existing statement parsing logic.
5. Return only accounts found in both sources, in the existing response format, with totals for the accounts returned and the existing masking. Snowflake accounts without an S3 folder are not returned. If nothing matches, return 200 with zero totals and accounts []. If Snowflake or S3 fails, return an error, never 200 with an empty list.

FLOW WHEN AN ACCOUNT NUMBER IS GIVEN
Run the same query with one more bind: AND a.CUSTOMER_ACCOUNT_NBR = <account bind>. If it returns a row, run the existing single-account statement lookup. Don't load the full account list.
